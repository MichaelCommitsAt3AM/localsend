# LocalSend AutoSync 1.0.0

The first release of this LocalSend fork adds automatic clipboard sharing between
Windows and Android. Copy on one paired device, then paste on the other. Regular
LocalSend file and message transfers remain available.

This is an initial development release. Windows and Android are the only release
targets; Linux and macOS support is deferred. Clipboard sharing works directly
over your local network, with no hosted relay or cloud clipboard storage.

## What's included

- Automatic two-way sharing of new plain-text clipboard copies.
- Optional copied-photo and screenshot sharing through **Synchronize copied images**.
- Automatic sharing of newly saved Android screenshots from standard screenshot
  albums when full photo access is granted.
- QR and nearby-device pairing, with matching codes and approval on both devices.
  Camera-app QR links can open LocalSend through the pairing website.
- Device cards with green connection dots, per-device send/receive permissions,
  and confirmation before removing a device.
- Background operation through the Windows tray and Android's clipboard service.
- Image-arrival notifications on both devices; text arrivals are silent. Android's
  ongoing notification lists only connected devices.
- Android setup guidance for Shizuku, permissions and pairing.
- LocalSend teal as the default color.
- In-app checks for this fork's GitHub updates, verified downloads, and a separate
  action to open the installer. Updates are not installed silently.

## Downloads and installation

| File | Target |
| --- | --- |
| `LocalSend-1.0.0-windows-x86-64.exe` | Windows x64 installer |
| `LocalSend-1.0.0-android-universal.apk` | Android universal APK |

The Windows installer is unsigned and may trigger publisher or SmartScreen
warnings. It uses a separate fork installation directory and installer identity.

The Android APK is signed with this fork's permanent release key. It retains
`org.localsend.localsend_app`, so **uninstall official LocalSend first**: the two
apps cannot coexist or update one another because their signing keys differ.
Uninstalling removes the official app's data. Existing debug builds use a separate
package and cannot be updated in place by this release APK; configure permissions
and clipboard pairing again in the release app.

## Start sharing

1. Install this fork on both devices and connect them to the same reachable local
   network. Guest Wi-Fi and client isolation can prevent a connection.
2. On Android, install [Shizuku](https://shizuku.rikka.app/download/) and start it
   using wireless debugging or a computer. In **Settings > Clipboard sync**, use
   **More > Setup tutorial** and authorize LocalSend and notifications. Restart
   Shizuku after a phone reboot.
3. On Windows, choose **Add device**. Scan its QR code on Android, compare the
   displayed codes and approve on both devices.
4. Enable **Share clipboard** on both devices. A green device dot indicates an
   active clipboard connection. Copy new text and paste on the other device.
5. For photos and screenshots, enable **Synchronize copied images** on both devices.
   Grant full photo access on Android for automatic screenshot sharing.

Keep Windows LocalSend running in the tray and Android's clipboard service active.
Force-stopping the Android app stops synchronization. Local clipboard connections
use TCP 53318; pairing temporarily uses TCP 53319.

## Privacy, limits and validation

Sharing is disabled by default and uses explicitly paired identities with pinned
mutual TLS 1.3. There is no clipboard history, clipboard-content logging or
forwarding between peers. Pair only devices you control and trust. Sensitive-marked
clips are skipped, but unmarked text and screenshots may still contain private data.

Text is limited to 64 KiB. Supported images are normalized to PNG and limited to
8 MiB and 16 megapixels. Automatic Android screenshot sharing recognizes standard
`DCIM/Screenshots` and `Pictures/Screenshots` albums; ordinary saved camera photos
must be explicitly copied. Rich text and remote clipboard clearing are unsupported.

Delivery is best effort and keeps the latest value. Sleep, locked-screen access,
provider restrictions and changing device IP addresses can affect sharing; saved
address changes may require re-pairing. Android clipboard integration targets
Android 13-16 with Shizuku's debugging startup mode. Physical validation has been
performed on a Galaxy A35 running Android 16, not every supported device/version.

Windows and Android release builds succeeded in GitHub Actions. Earlier debug
testing covered text, images, screenshots and background sharing; release-install,
camera-link and upgrade validation still need to be completed before publishing
this draft. Independent security review and extended reliability testing remain
pending.
