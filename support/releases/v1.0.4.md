# LocalSend AutoSync 1.0.4

This update restores file-transfer service recovery when clipboard sync still
works but devices disappear or transfers fail with HTTP 500. Android build
number: 69.

## Changes

- Detect an exited file-transfer isolate, close its outstanding event streams,
  and recreate the service automatically. This addresses a server that keeps
  listening after losing the application handler for transfer requests.
- Check authenticated HTTP readiness when the mobile app resumes. The previous
  TCP-only probe could report success while transfer requests failed. The server
  now reports an unavailable application event receiver through its info endpoint.
- Bound clipboard discovery TLS handshakes and release stalled connections so
  one unresponsive address cannot block later pairing-address refreshes.

Install over the previous AutoSync release to retain settings and pairing.
The debug Android app uses a separate package and pairing configuration.
Windows installers are unsigned.

## Validation

The phone's HTTP 500 failure was reproduced against its live transfer service.
After installing the patched Android debug build on the Galaxy A35, the user
confirmed transfers working. Focused tests cover receiver loss, isolate exit,
HTTP readiness, mutual TLS, timeouts, discovery and clipboard address refresh.
Recovery after extended background suspension still needs device verification;
the original trigger for the handler failure has not been confirmed.
