# LocalSend AutoSync 1.0.6

This update fixes a one-way connection failure where Android could see the Windows device but could not send to it or sync the clipboard until the app was restarted. Android build number: 73.

## Changes

- Prefer a device's verified local address over an address it was only seen connecting from. Previously, a routed or NAT-translated source address could replace a working LAN address, causing sends to time out (`os error 110`) until the app was restarted.
- Check connections every 15 seconds while the app is open: restart the file-transfer server if its sockets died, and recover clipboard sync after a sustained disconnect without interrupting connected devices.
- Devices added by address are shared with nearby discovery and clipboard address recovery.

## Downloads

- `LocalSend-1.0.6-android-arm64-v8a.apk`: signed Android ARM64 release APK.
- `LocalSend-1.0.6-windows-x86-64.exe`: Windows x64 installer.
- `LocalSend-1.0.6-windows-arm-64.exe`: Windows ARM64 installer.

Install over the previous AutoSync release to retain settings and pairing. Update both devices; the address fix applies to whichever device is dialing. Windows installers are unsigned.

## Validation

On a Galaxy A35 and Windows on the same LAN, a debug build with the address fix chose the PC's LAN address and delivered a phone-to-PC send that previously timed out. Unit tests cover address ranking, including the original failing case. The original trigger did not recur during testing, and how the routed address first appeared is still unconfirmed. See `support/clipboard_sync/DEBUG_RESULTS.md`.
